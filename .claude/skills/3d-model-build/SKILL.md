# 3D model build (this repo's conventions)

This repo is a collection of print-ready models, each generated by a
self-checking FreeCAD Python script. The value of the collection is that
every model follows the *same* shape — same folder layout, same class of
self-check, same README structure — so don't improvise a new structure
per model. This skill exists to keep that consistent without re-deriving
it (and re-spending the tokens) every time.

**Reference implementation:** [`whiteboard-stand/freecad/build_caddy.py`](../../../whiteboard-stand/freecad/build_caddy.py)
(~1200 lines). Don't duplicate its contents here — open it and copy/adapt
the relevant functions when building a new model. It is the canonical
example of every pattern below.

## When extending vs. creating new

- **New variant of an existing model** (like `whiteboard-stand-3-eraser` was
  to `whiteboard-stand`): copy the existing model's whole folder, rename,
  then edit the PARAMS dict / geometry functions for what actually changed.
  Don't rebuild from scratch — the point of the parametric script is that
  small changes are small diffs.
- **Genuinely new model**: follow the full scaffold below.

## Folder layout

Every model is a top-level directory, sibling to `whiteboard-stand/`:

```
<model-name>/
  README.md              what it is, print settings, how to change it
  images/                renders used in the READMEs
  freecad/
    build_<name>.py      the generator — re-runnable, self-checking
    <name>.FCStd          FreeCAD document (committed)
    exports/              STEP + STL + 3MF, committed and ready to slice
```

Model name is kebab-case (`whiteboard-stand-3-eraser`), matching the repo
folder and the root README table row.

## The build script

One Python file, run headless via `freecadcmd build_<name>.py` (macOS:
`/Applications/FreeCAD.app/Contents/Resources/bin/freecadcmd`). It must be
fully re-runnable — every invocation rebuilds the FreeCAD document from
scratch and re-exports, so the user can change one number and get a new
part with no manual steps in between. Structure, modeled on `build_caddy.py`:

1. **Module docstring** — what it builds, the as-shipped configuration (real
   counts/sizes of what it holds, not placeholders), how to run it, and a
   short list of what the checks verify. This docstring is what a future
   session reads instead of the code, so make it stand alone.

2. **`PARAMS` dict** — every number a user might plausibly want to change
   (material thickness, object counts, tolerances, clearances) lives here,
   not scattered through geometry code. Written into a FreeCAD Spreadsheet
   object in the doc (`write_spreadsheet`) as a record of what was used —
   this is what lets someone open the `.FCStd` later and see exactly what
   config produced it.

3. **`derive(p)`** — takes `PARAMS`, returns every *computed* dimension
   (wall positions, cutout sizes, offsets) as one dict. Geometry functions
   read only from this derived dict, never recompute from `PARAMS` directly.
   This is what makes "change one number, re-run" actually work — one
   source of truth for the math.

4. **Geometry builder functions** (`make_*`, `build_*`) — one function per
   logical sub-assembly (a wall, a bay, a tube row), fused together into the
   final solid. Keep these boring and mechanical; put judgment calls (why a
   dimension is what it is) in comments near `PARAMS`, not buried in a
   boolean-op call.

5. **`build_coupon()` — the fit coupon.** A small separate part carrying
   only the dimensions that depend on objects the *user* owns (a marker's
   actual diameter, a board's actual thickness) — not the ones the model was
   designed around. This is what lets someone find out a marker is 0.5mm too
   tight in 20 minutes instead of after an overnight print. Every model
   ships one; treat "no fit coupon" as incomplete, not optional, for any
   model whose fit depends on a physical object the user owns rather than a
   fixed engineering tolerance.

6. **Self-checks**, run and reported on every build. Reuse these patterns
   from `build_caddy.py` rather than reinventing the check logic:
   - **`check_fits`** — a probe solid of each real object is pushed through
     the model; any intersection means it will not physically fit. This is
     the check that has caught real bugs (see repo history) — don't skip it
     for a model that holds specific objects.
   - **structural** — minimum wall/web thickness at the spots that would
     actually break, not a blanket check everywhere.
   - **`overhangs`** — classifies downward-facing faces into true flat
     bridges vs. harmless progressive overhang, so the printability verdict
     isn't just "has overhangs = bad."
   - **`watertight`** — B-rep self-intersection, closed shell, non-manifold
     tessellation. A slicer will silently produce garbage or reject a mesh
     that fails this, so catch it before export, not after a failed slice.

   If a check fails, fix the *script* (geometry or params), not the
   exported mesh. Don't run output through a mesh-repair tool as a
   workaround — that hides a real modeling bug instead of fixing it.

7. **`export_all`** — exports STEP, STL and 3MF for every named part (the
   real model, the coupon, any sub-pieces), with a `fine_mesh` tessellation
   pass before STL/3MF export. Run this for every part on every build so
   `exports/` is never stale relative to the script.

8. **`run()`** — orchestrates: build → check → export → print a report.
   This is the function a user actually invokes; keep the console output
   readable, since it's the first thing they see when validating a change.

## READMEs

Two READMEs change for every new model or variant. Copy the structure
verbatim from the existing entries — don't reformat.

**Root [`README.md`](../../../README.md):**
- Add a row to the models table: `| **[Name](model-dir/)** | one-line what
  it is | LxWxH mm | print time · weight material · supports note | status
  emoji + text |`. Status is `✅ Printed and in use` (or similar, once
  actually printed) or `🧪 Generated and checked, not yet printed` (once the
  script runs clean but before a real print) — don't claim "printed" status
  until it has been.
- Add a prose section below the table, same shape as the existing "Whiteboard
  Caddy" sections: heading, image, one paragraph of what it does, a bolded
  "holds X, Y, Z" sentence, link to the model's own README.
- If the model has any use-specific safety concern (heat, small parts,
  load-bearing), extend the root **Safety** section rather than burying it
  only in the per-model README — that section is the one place a reader
  checks once for the whole collection.

**Per-model `<model-name>/README.md`** — follow
[`whiteboard-stand/README.md`](../../../whiteboard-stand/README.md) exactly:
title, one paragraph description, image, "holds X" sentence, a spec table
(Size / Print time / Material / Supports / Bed needed / Status), a "Print
these" section linking the coupon export first and the real part second
(explain in one line what the coupon proves), a "Change it" section pointing
at the `PARAMS` dict, and the standard footer linking back to root README's
safety section and license.

## Checklist for a new model

1. Copy folder structure (or an existing model's folder, if it's a variant).
2. Write/adapt `build_<name>.py` — PARAMS, derive, geometry, coupon, checks,
   export, run. Base it on `build_caddy.py`'s structure.
3. Run it via `freecadcmd`, confirm the report shows fit/structural/
   printability/mesh checks all passing, and `exports/` has fresh
   STEP/STL/3MF for every part.
4. Write the per-model README.
5. Add the table row + prose section to the root README, and extend Safety
   if warranted.
6. Status starts as 🧪 until an actual print confirms it — update the row
   and per-model README's Status field once it's printed.
